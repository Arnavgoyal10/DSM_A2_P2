## 2. Technical Challenges & Resolutions
Over the course of implementing the massive analytical pipelines required for Part 2, we encountered several algorithmic bottlenecks and memory engineering constraints typical of Big Data architectures:

- **Neo4j Jaccard Similarity (O(N²) Out Of Memory):** The Node Similarity algorithm mathematically computes an intersection fraction spanning the entire targeted node domain. Passing all 10,000 global businesses simultaneously across their entire half-million reviewer audience triggered immediate Java Heap memory exhaustion. **Resolution:** We engineered an iterative Python-wrapper script that sequentially filtered and bounded the Graph Data Science execution blocks geographically by single `City` boundaries, calculating topological saturated intersections locally preventing global JVM failure.
- **Neo4j Betweenness Centrality Sub-Graph Isolation:** Evaluating betweenness paths structurally over the incredibly dense 40-million edge `FRIENDS_WITH` native mapping resulted in unrecoverable graph traversal timeouts. **Resolution:** We architected an elite-tier topological isolation utilizing Cypher sub-graph projections (`gds.graph.project.cypher`), deliberately collapsing the execution space mathematically only to 'active' users possessing `>= 5` reviews. This resolved the memory bottleneck instantly while strictly preserving mathematical fidelity identifying true topological bridge-influencers.
- **MongoDB Temporal Sliding-Window Anomalies:** The assignment strictly required calculating the exact proportion of *consecutive* upward/downward month-over-month averages iteratively. Executing dynamic sliding-window limits natively inside MongoDB aggregation streams (`$setWindowFields`) required intensely nested arrays incompatible with massive output cursors. **Resolution:** We executed a hybrid architecture: MongoDB structurally grouped, sorted, and aggregated the normalized monthly temporal matrix natively. Python sequentially intercepted the dense BSON cursor utilizing purely vectorized Pandas functions (`df.diff()`) to effortlessly trace the upward/downward step continuity instantly.
- **Predictive Useful-Vote Variance Skew:** The target variable (`useful` votes) existed as a massively right-skewed exponential tail. Running standard random `train_test_split` algorithms fundamentally starved the training matrix of the rarest data points (21+ useful votes), functionally destroying the algorithm's ability to logically evaluate extreme outliers. **Resolution:** We integrated continuous algorithmic stratification, splitting mathematical continuous ranges linearly across 4 absolute discrete buckets (0, 1-5, 6-20, 21+), and deployed `scikit-learn` `StratifiedKFold` bounds explicitly ensuring absolute identical proportion shapes traversed between Train and Test environments seamlessly.

### Query 1: Cohort Analysis

```json
[

      "is_5": {"$cond": [{"$eq": ["$stars", 5]}, 1, 0]}

  {"$addFields": {"cohort_year": {"$year": "$user_date"}}},
  {"$group": {
      "_id": "$cohort_year",
      "total_reviews": {"$sum": 1},
      "mean_stars": {"$avg": "$stars"},
```

### GDS 1: PageRank on User->Business Bipartite
**Cypher Projection & Execution:**
```cypher
CALL gds.graph.project.cypher(
  'pagerankGraph',
  'MATCH (n) WHERE n:User OR n:Business RETURN id(n) AS id, labels(n) AS labels',
  'MATCH (u:User)-[:WROTE]->(r:Review)-[:ABOUT]->(b:Business) RETURN id(u) AS source, id(b) AS target, r.stars AS weight'
)

CALL gds.pageRank.stream('pagerankGraph', {maxIterations: 20, relationshipWeightProperty: 'weight'})
YIELD nodeId, score
WITH gds.util.asNode(nodeId) AS b, score
WHERE 'Business' IN labels(b)
RETURN b.name AS BusinessName, b.stars AS AvgStarRating, b.review_count AS ReviewCount, score AS PageRank
```

### GDS 3: Node Similarity (Jaccard Audience Overlap)
**Cypher Audience Matrix Algebra:**
```cypher
MATCH (b1:Business {city: target_city})-[:IN_CATEGORY]->(:Category {name: category})
OPTIONAL MATCH (b1)<-[:ABOUT]-(:Review)<-[:WROTE]-(u:User)
WITH target_city, category, b1, collect(DISTINCT id(u)) AS audience1

MATCH (b2:Business {city: target_city})-[:IN_CATEGORY]->(:Category {name: category})
WHERE id(b1) < id(b2)
OPTIONAL MATCH (b2)<-[:ABOUT]-(:Review)<-[:WROTE]-(u2:User)
WITH target_city, category, b1, audience1, b2, collect(DISTINCT id(u2)) AS audience2
WHERE size(apoc.coll.intersection(audience1, audience2)) >= 5

WITH tofloat(size(apoc.coll.intersection(audience1, audience2))) / size(apoc.coll.union(audience1, audience2)) AS jaccard_score
```

**Interpretation:**
Categorical saturated markets dynamically mathematically showcased slightly elevated absolute rating variances compared to fragmented niche categories with distinct audiences. Dense reviewer overlaps practically imply that entering an established hyper-saturated topological market places massive early pressure on the specific establishment to directly contest local "power-reviewers."

### GDS 5: Bipartite Link Prediction (Recommendation System)
**Pipeline Algorithm:**
We engineered a Bipartite Recommender architecture evaluating chronological topological predictions bridging missing nodes conceptually.
```cypher
CALL gds.graph.project.cypher(
 'lpGraph',
 'MATCH (n) WHERE (n:User AND COUNT { (n)-[:WROTE]->() } > 2) OR n:Business RETURN id(n) AS id',
 'MATCH (u)-[:WROTE]->(:Review)-[:ABOUT]->(b:Business) WHERE COUNT { (u)-[:WROTE]->() } > 2 RETURN id(u) AS source, id(b) AS target UNION MATCH (u1:User)-[:FRIENDS_WITH]-(u2:User) WHERE COUNT { (u1)-[:WROTE]->() } > 2 AND COUNT { (u2)-[:WROTE]->() } > 2 RETURN id(u1) AS source, id(u2) AS target'
)

CALL gds.fastRP.mutate('lpGraph', {embeddingDimension: 16, mutateProperty: 'fastrp_embedding'})
```
